# Implementation Plan

> Requirement ID mapping rule for this plan: `N.M` means "Requirement N の Acceptance Criteria M"。

- [ ] 1. Foundation: 比較実験の前提契約と判定ルールを固定する
- [ ] 1.1 比較メタデータを含む評価ログ契約を確定する
  - 比較セッションID、条件ID、提示順を評価ログに持たせ、既存ログとの後方互換ルールを明確化する。
  - CSV出力で条件比較に必要な列を追加し、既存分析列が欠落しない契約を確定する。
  - 完了条件: 比較メタデータ付きログを保存・再読込でき、旧ログも破綻せず扱える。
  - _Requirements: 1.2, 2.3, 3.4_
- [ ] 1.2 実験ルール（ランダム化・閾値・データ不足判定）を定義する
  - 条件提示のランダム化ルール、過信リスク閾値、データ不足判定閾値を固定する。
  - ルール値が保存・集計・表示で同一参照されるよう契約化する。
  - 完了条件: ルール定義を使って同じ入力で同じ判定結果を再現できる。
  - _Requirements: 2.1, 3.3, 4.2_
- [ ] 1.3 条件欠損時の再試行/スキップ方針を確定する
  - 条件出力取得失敗時に、再試行とスキップのどちらを提示するかを状態遷移として定義する。
  - 欠損条件を実験ログに残す表現を定義する。
  - 完了条件: 欠損条件発生時に利用者が再試行またはスキップを選択でき、選択結果が記録される。
  - _Requirements: 1.3_

- [ ] 2. Core: 比較実験のドメイン機能を境界ごとに実装する
- [ ] 2.1 (P) 比較セッション管理と条件提示順ランダム化を実装する
  - A/B/C 条件の提示順をセッション単位で生成し、同一セッションで順序を固定する。
  - 比較対象の前提入力（本文・テーマ・媒体種別）が条件間で一致することを保証する。
  - 完了条件: 実験開始時に条件順が生成され、セッション終了まで不変で参照できる。
  - _Requirements: 1.1, 1.2, 1.4, 2.1_
  - _Boundary: ExperimentSessionManager_
- [ ] 2.2 (P) 条件別統計集計と分布算出を実装する
  - 条件別の平均評価（正確性・有用性・信頼性）を算出する。
  - 修正理由分布とデータ不足判定フラグを条件単位で返す。
  - 完了条件: 条件別の平均値・分布・不足判定が同一ログ集合から安定再現される。
  - _Requirements: 3.1, 3.2, 3.3, 3.4_
  - _Boundary: ConditionDashboardAggregator_
- [ ] 2.3 (P) 過信リスク指標と警告判定を実装する
  - 高信頼評価かつ修正発生の組み合わせを条件別に算出する。
  - 閾値を超えた条件に警告判定を付与し、品質自動断定を行わない。
  - 完了条件: 条件別リスク値と警告フラグが算出され、解釈補助として参照できる。
  - _Requirements: 4.1, 4.2, 4.4_
  - _Boundary: OverconfidenceRiskCalculator_
- [ ] 2.4 条件別評価入力の検証ロジックを実装する
  - 5段階評価、修正理由、コメント入力の整合性を条件単位で検証する。
  - 未入力送信時に欠落項目を識別して返す。
  - 完了条件: 入力不備時は保存されず、利用者が不足項目を特定できる。
  - _Requirements: 2.2, 2.3, 2.4_

- [ ] 3. Integration: API と UI に比較実験フローを統合する
- [ ] 3.1 研究ログAPIを比較メタデータ対応へ拡張する
  - 比較セッションID、条件ID、提示順を保存・取得できるようにする。
  - 後方互換ログ読み込み時のデフォルト補完を実装する。
  - 完了条件: 比較メタデータ付き評価ログを保存・取得し、既存ログも同APIで読める。
  - _Depends: 1.1_
  - _Requirements: 1.2, 2.3, 3.4_
- [ ] 3.2 分析APIの条件比較入力を統合する
  - 条件識別子付き分析要求を受け付け、欠損時の再試行/スキップ判断に必要な情報を返す。
  - 条件差以外の入力前提が統一されるよう検証する。
  - 完了条件: 条件付き分析要求でA/B/C比較に必要な応答を返し、欠損条件を明示できる。
  - _Depends: 1.3, 2.1_
  - _Requirements: 1.1, 1.3, 1.4_
- [ ] 3.3 Studio UI に比較実験、評価フォーム、条件別ダッシュボードを統合する
  - 比較実験開始、ランダム条件提示、条件別評価入力、保存、条件別統計表示を単一導線で扱う。
  - 過信リスク警告と算出根拠（件数・内訳）を表示する。
  - 完了条件: 利用者が A/B/C 比較実験を完了し、条件別統計と過信リスクを同一画面で確認できる。
  - _Depends: 2.1, 2.2, 2.3, 2.4, 3.1, 3.2_
  - _Requirements: 1.1, 2.2, 2.4, 3.1, 3.2, 3.3, 4.2, 4.3_
- [ ] 3.4 CSV出力を条件比較対応へ統合する
  - 条件列を含む研究データ出力を実装し、既存出力項目との互換を維持する。
  - 条件別再分析に必要な最小情報が欠落しないことを検証する。
  - 完了条件: CSV出力に条件比較列が含まれ、既存ログ/比較ログの双方を正しく書き出せる。
  - _Depends: 1.1, 2.2_
  - _Requirements: 3.4, 4.3_

- [ ] 4. Validation: 受け入れ基準を実験導線で検証する
- [ ] 4.1 ドメインロジックのユニットテストを実装する
  - ランダム提示順、条件別統計、過信リスク算出、未入力ガードを個別検証する。
  - 完了条件: 主要ドメインロジックのテストが再現可能に通過する。
  - _Requirements: 2.1, 2.4, 3.1, 3.2, 4.1, 4.2, 4.4_
- [ ] 4.2 API統合テストを実装する
  - 比較メタ保存、条件付き分析、欠損条件ハンドリング、データ不足判定を検証する。
  - 完了条件: 比較実験に必要な API 応答が契約どおり返る。
  - _Requirements: 1.2, 1.3, 1.4, 2.3, 3.3, 3.4_
- [ ] 4.3 E2E/UI 検証を実施する
  - 比較開始 -> ランダム提示 -> 条件評価入力 -> 保存 -> 条件別ダッシュボード確認の導線を検証する。
  - 過信リスク警告と根拠内訳表示が期待通り出ることを確認する。
  - 完了条件: 実験フロー全体が手戻りなく完了し、主要指標を確認できる。
  - _Requirements: 1.1, 2.2, 2.4, 3.1, 3.2, 4.2, 4.3_
